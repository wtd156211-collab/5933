# 任务：可视化工作流查看与执行回放

角色设定：

你是一名资深全栈工程师，擅长工作流引擎、异步任务调度、状态机、前后端状态同步和交互式流程图开发。你需要优先理解当前仓库已有的工作流执行逻辑和前端结构，在不破坏既有行为的前提下完成改动。你重视状态一致性、错误处理、可测试性和实际页面验证，不会用静态数据或占位交互掩盖未完成的功能。

请在当前仓库中完成以下代码任务：

基于现有的工作流、任务执行或流程编排模块，增加一个可视化工作流查看与执行回放功能。请先检查仓库中已有的相关后端逻辑、数据模型、接口、前端页面和测试，在现有架构基础上完成修改。不要创建与当前项目无关的独立 Demo；如果仓库中没有足够的相关基础，请实现与现有项目最接近的最小集成范围，并明确说明限制。

技术栈建议：

- 前端：React + TypeScript；如果仓库已有其他前端框架，应优先沿用现有框架。
- 图展示：优先使用仓库已有的流程图或节点图组件；如果没有，可使用 React Flow 或同类轻量方案。
- 状态获取：优先使用现有 API 和轮询机制；只有仓库已有实时通信基础时，才使用 WebSocket 或 SSE。
- 后端和数据层：沿用仓库已有的语言、接口层和数据存储方案。

技术栈说明：

React 和 TypeScript 用于构建类型安全的交互界面；流程图库用于展示工作流节点和依赖关系；现有 API 或轮询机制用于获取执行状态。不得为了引入上述技术栈而替换仓库已有框架。

要求：

1. 展示一个已有工作流的节点及其依赖关系，支持查看节点名称、依赖关系和基本状态。
2. 对循环依赖或缺失依赖给出明确错误，并阻止该工作流进入回放或执行展示流程。
3. 支持展示 pending、running、success 和 failed 四种核心状态；其他状态可以沿用仓库已有实现，但不要求新增完整的状态机。
4. 用户可以选择一条已经完成或失败的历史执行记录，通过时间轴或逐步操作查看节点状态变化。
5. 正确处理执行记录中的节点顺序与拓扑顺序不一致，以及部分节点记录缺失的情况，并给出合理提示。
6. 如果仓库已有重试或取消逻辑，只需要保证已有逻辑在可视化展示中不被破坏，不要求新增完整的暂停、恢复和实时控制系统。
7. 如果仓库已有前端，应实际运行页面并验证工作流展示、历史记录选择和回放操作；不得使用静态截图或硬编码数据替代真实接口。
8. 保持现有公开接口和已有行为兼容，只修改完成任务所必需的文件，不进行无关重构。
9. 补充回归测试，至少覆盖正常工作流、循环依赖、执行失败、历史回放和缺失执行记录等场景。
10. 运行相关测试、类型检查、构建命令和必要的页面验证。
11. 如果某项要求受现有仓库能力限制无法完整实现，请明确说明限制、已完成部分和未验证风险，不要虚构已实现功能。
12. 最终总结修改的文件、核心行为变化、实际运行的验证命令、验证结果和剩余风险。

# 项目说明（实现部分）

仓库初始为空（无既有工作流引擎或前端），因此按任务要求实现了最小集成范围的完整全栈应用。

## 结构

- `shared/` — 前后端共享的 TypeScript 领域逻辑：`types.ts`（数据模型）、`workflow.ts`（DAG 校验：循环/缺失依赖检测、拓扑分层）、`replay.ts`（回放帧计算与异常记录警告）
- `server/` — Express API + 内存存储 + 异步执行引擎（`src/engine.ts`），端口 3001
- `web/` — React + TypeScript + Vite + React Flow 前端，端口 5173（`/api` 代理到 3001）

## API

- `GET /api/workflows` — 工作流列表
- `GET /api/workflows/:id/graph` — 节点、边与校验错误（非法工作流返回 `errors`，前端据此阻止运行/回放）
- `POST /api/workflows/:id/executions` — 启动执行（非法工作流返回 422）；异步执行，立即返回 `running` 记录
- `GET /api/workflows/:id/executions` — 历史执行列表
- `GET /api/executions/:id` — 执行详情（含带时间戳的节点状态事件流）

## 常用命令

```bash
npm install          # 安装全部 workspace 依赖
npm test             # vitest：26 个回归测试（校验/引擎/回放/API）
npm run typecheck    # server + web 的 tsc --noEmit
npm run build        # web 生产构建（含类型检查）
npm run start --workspace server   # 启动后端 :3001
npm run dev --workspace web        # 启动前端 :5173
```

## 内置示例数据

- `order-pipeline`：合法的订单流水线（5 节点钻石型 DAG）
- `cyclic-workflow` / `broken-workflow`：循环依赖 / 缺失依赖的非法工作流，用于验证错误提示与阻断
- 种子执行记录：`exec-success-1`（成功）、`exec-failed-1`（扣款失败、下游跳过）、`exec-legacy-1`（事件顺序与拓扑不一致且缺少 notify 节点记录，用于验证回放警告）
